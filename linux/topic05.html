fork() vs exec()
기출 포인트: 두 함수의 동작 방식 차이
함수동작메모리
fork()기존 프로세스를 복제해서 새 프로세스 생성새 메모리 할당 O
exec()호출 프로세스가 새 프로세스로 교체새 메모리 할당 X
📌 동작 원리

사용자 로그인 → bash 프로세스 할당 → 명령어 입력 → fork() 형태로 자식 프로세스 생성

CentOS 7: 부팅 시 커널이 systemd 발생 → PID 1 부여 → 다른 서비스는 fork()로 자식 생성

시그널 번호 ⭐⭐⭐
기출 포인트: SIGINT(2), SIGKILL(9), SIGTERM(15), SIGTSTP(20) 번호
번호이름발생 조건동작
1SIGHUP터미널 연결 끊김종료 후 재시작
2SIGINTCtrl+C강제종료
3SIGQUITCtrl+\코어 덤프
9SIGKILL프로세스 강제종료 시무조건 강제종료 (무시 불가)
15SIGTERMkill 명령 기본 시그널정상종료 시도
18SIGCONT중지된 프로세스 재실행무시
19SIGSTOP-SIGCONT 받을 때까지 정지
20SIGTSTPCtrl+Z프로세스 대기(suspend)
⭐ 반드시 암기

Ctrl+C = 2(SIGINT) | Ctrl+Z = 20(SIGTSTP)

kill 기본 = 15(SIGTERM) | 강제종료 = 9(SIGKILL)

시그널 번호 확인: kill -l

명령어설명주요 옵션
ps실행 중인 프로세스 상태a(모든), u(사용자+시작시간), x(터미널없는것 포함)
top실시간 CPU/메모리 모니터링k(kill), n(개수지정), r(NI값변경), q(종료)

killPID로 프로세스 종료-l(시그널목록), -9(강제종료)
killall프로세스 이름으로 종료ex) killall firefox
jobs백그라운드 작업 목록 확인-l(PID포함)
nohup터미널 닫혀도 백그라운드 계속 실행명령어 뒤에 & 함께 사용
ps aux # 모든 프로세스 정보 kill 1234 # PID 1234 정상종료(SIGTERM) kill -9 1234 # PID 1234 강제종료 kill %2 # 작업번호 2번 백그라운드 종료 killall firefox # firefox 이름의 모든 프로세스 종료 nohup tar cvf backup.tar /data & # 백그라운드로 계속 실행

📌 NI 값 범위

범위: -20 ~ 19 (-20이 최고 우선순위, 19가 최저)

일반 사용자: NI값 증가만 가능 | root: 증가/감소 모두 가능

nice 옵션 없으면 디폴트 10 증가

nice -10 bash # bash를 NI +10으로 실행 (기본값이 -5이면 -5+10=5) renice 20 3241 # PID 3241의 NI값을 20으로 변경 renice -10 bash # bash 프로세스명으로 NI -10 설정
